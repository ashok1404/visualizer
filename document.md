
## Error JSON (reference)

Here is an example `error.rcb` payload showing the JSON fields required to
format the error in Error Explorer:

```json
{
  "msg": "App crashed with SIGSEGV, signo: 11, errno: 1, signal code: 1, identified through Matric Kit~~Example-UIKit  0x0000000104d09aa0 Example-UIKit + 55968",
  "eTp": "NativeAppCrash",
  "time": 1788952320000,
  "NATIVEAPP": {
    "sdkId": "btt-swift-sdk",
    "eMeta": "[signal: 11, exceptionCode: 1, exceptionType: 1, appBuildVersion: \"1\", platformArchitecture: \"arm64e\", regionFormat: \"IN\", isTestFlightApp: false, lowPowerModeEnabled: false]",
    "stackTrace": "{\"meta\":{\"fVersion\":\"1.0.0\"},\"threads\":[{\"id\":\"0\",\"crashed\":true,\"name\":\"Main Thread\",\"stack\":[{\"i\":0,\"fLine\":\"dyld  0x00000001852d9c1c dyld + 19484\"},{\"i\":1,\"fLine\":\"Example-UIKit  0x0000000104d09aa0 Example-UIKit + 55968\"}]}]}"
  }
}
```

`eMeta` and `stackTrace` arrive as **strings**, not nested objects — decode
each separately (see below).

---

## 1. `msg`

The human-readable message describing the error/crash, generated by the SDK. Sent in the `msg` property of `error.rcv`.

```
POST https://d.btttag.com/err.rcv?
[
  {
    ...
    "msg": "App crashed with SIGSEGV, signo: 11, errno: 1, signal code: 1, identified through Matric Kit~~Example-UIKit  0x0000000104d09aa0 Example-UIKit + 55968",
    ...
  }
]
```

Used as the title shown in the **Error Explorer's Top Errors** table, in the
**Error Message** column. Keep the full message as-is.

## 2. `eTp`

Fatal and non-fatal errors tracked by the Android, iOS, and React Native SDKs each carry a unique error type. These constants are sent in the `eTp` property of `error.rcv`.

```
POST https://d.btttag.com/err.rcv?
[
  {
    ...
    "eTp" : "NativeAppCrash",
    ...
  }
]
```

Used in the **Error Explorer's Top Errors** table, in the **Error Type**
column.

| No | eTp | Platform | SDK Version | Description |
|---|---|---|---|---|
| 1 | `NativeAppCrash` | iOS, Android | | iOS: Blue Triangle tracks Apple MetricKit CrashDiagnostic reports. MetricKit issues this diagnostic when your app terminates unexpectedly.<br>Android: |
| 2 | `ANRWarning` | iOS, Android | | |
| 3 | `MemoryWarning` | iOS, Android | | |
| 4 | `ForceRestart` | iOS, Android | | |
| 5 | `ExcessCPUUsage` | iOS | | |
| 6 | `HeavyDiskWrite` | iOS | | |
| 7 | `SlowLaunch` | iOS | | |
| 8 | `FatalANR` | Android | | |

## 3. `eMeta`

Structured metadata about the error/crash — env-specific details. Sent in the `eMeta` property of `NATIVEAPP` in `error.rcv`.

```
POST https://d.btttag.com/err.rcv?
[
  {
    ...
    "NATIVEAPP": {
      ...
      "eMeta": "[signal: 11, ...]",
      ...
    }
  }
]
```

Shown on the **Error Detail (Error Drilldown)** screen in Error Explorer —
which type of error, and which environment (app version, OS, device, etc).

Decode it (JSON string, or a Swift bracket-dump like `[signal: 11, ...]`) to
get:

```json
{
  "signal": 11,
  "exceptionCode": 0,
  "exceptionType": 1,
  "totalCPUTime": "45 seconds",
  "totalSampledTime": "60 seconds",
  "writesCaused": "1,024 MB",
  "hangDuration": "1.2 seconds",
  "launchDuration": "3.5 seconds",
  "appBuildVersion": "42",
  "platformArchitecture": "arm64e",
  "regionFormat": "US",
  "isTestFlightApp": false,
  "lowPowerModeEnabled": false
}
```

| Field | When it appears |
|---|---|
| `signal`, `exceptionCode`, `exceptionType`, `isTestFlightApp`, `lowPowerModeEnabled`, `regionFormat`, `hangDuration`, `launchDuration`, `totalCPUTime`, `totalSampledTime`, `writesCaused` | Optional Value |
| `appBuildVersion`, `platformArchitecture` | Environment info — always present |

## 4. `stackTrace`

### 4.1 Raw field

The full thread and frame data captured at the time of the error/crash. Sent in the `stackTrace` property of `NATIVEAPP` in `error.rcv`.

```
POST https://d.btttag.com/err.rcv?
[
  {
    ...
    "NATIVEAPP": {
      ...
      "stackTrace": "{\"meta\":{\"fVersion\":\"1.0.0\"},\"threads\":[...]}",
      ...
    }
  }
]
```

Also shown on the **Error Detail (Error Drilldown)** screen — decode the
string (`JSON.parse`), then combine data thread-wise using `index + fLine`:

```json
{
  "meta": {
    "fVersion": "1.0.0"
  },
  "threads": [
    {
      "id": "1",
      "name": "Main Thread",
      "crashed": true,
      "stack": [
        {
          "i": 0,
          "bId": "A1B2C3D4-E5F6-4A3B-9C8D-1E2F3A4B5C6D",
          "fLine": "libsystem_pthread.dylib        0x00000001e805e8cc libsystem_pthread.dylib + 2252"
        }
      ]
    }
  ]
}
```

Pattern — one thread block per entry in `threads[]`, one line per frame:

```
Thread[] crashed = true → Crashed
  Thread[].stack[0].i   Thread[].stack[0].fLine
  Thread[].stack[1].i   Thread[].stack[1].fLine
  Thread[].stack[2].i   Thread[].stack[2].fLine

Thread[] (not crashed)
  Thread[].stack[0].i   Thread[].stack[0].fLine
  Thread[].stack[1].i   Thread[].stack[1].fLine
```

### 4.2 Full formatting — from `error.rcv` to display text

All three (`msg`, `eTp`+`eMeta`, `stackTrace`) put together, the way the
**Error Detail (Error Drilldown)** screen shows a complete crash. This is the
same format used by the app's Download Report (`.txt`) output.

```
POST https://d.btttag.com/err.rcv?
[
  {
    "msg": "App crashed with SIGSEGV, signo: 11, errno: 1, signal code: 1, identified through Matric Kit~~Example-UIKit  0x0000000104d09aa0 Example-UIKit + 55968",
    "eTp": "NativeAppCrash",
    "time": 1788952320000,
    "NATIVEAPP": {
      "sdkId": "btt-swift-sdk",
      "eMeta": "[signal: 11, exceptionCode: 1, exceptionType: 1, appBuildVersion: \"1\", platformArchitecture: \"arm64e\", regionFormat: \"IN\", isTestFlightApp: false, lowPowerModeEnabled: false]",
      "stackTrace": "{\"meta\":{\"fVersion\":\"1.0.0\"},\"threads\":[{\"id\":\"0\",\"crashed\":true,\"name\":\"Main Thread\",\"stack\":[{\"i\":0,\"fLine\":\"dyld  0x00000001852d9c1c dyld + 19484\"},{\"i\":1,\"fLine\":\"Example-UIKit  0x0000000104d09aa0 Example-UIKit + 55968\"}]}]}"
    }
  }
]
```

This is the full `msg` + `eTp` + `NATIVEAPP` payload — no fields left out — since
this section combines all 4 points above into the one displayed crash.

Pattern — which data comes from where:

```
Platform:      NATIVEAPP.sdkId
Date/Time:     time

Hardware Model:      NATIVEAPP.eMeta.deviceType
Version:             NATIVEAPP.eMeta.appVersion (NATIVEAPP.eMeta.appBuildVersion)
Code Type:           NATIVEAPP.eMeta.platformArchitecture
OS Version:          NATIVEAPP.eMeta.osVersion
Exception Code: NATIVEAPP.eMeta.exceptionCode
Exception Sub Type: NATIVEAPP.eMeta.exceptionType
Region: NATIVEAPP.eMeta.regionFormat
TestFlight: NATIVEAPP.eMeta.isTestFlightApp
Low Power Mode: NATIVEAPP.eMeta.lowPowerModeEnabled
Hang Duration: NATIVEAPP.eMeta.hangDuration (if present)
Launch Duration: NATIVEAPP.eMeta.launchDuration (if present)
Total CPU Time: NATIVEAPP.eMeta.totalCPUTime (if present)
Sampled Time: NATIVEAPP.eMeta.totalSampledTime (if present)
Disk Writes: NATIVEAPP.eMeta.writesCaused (if present)

Exception Type:  NATIVEAPP.eMeta.signal (mapped to signal name)
Exception Note:  msg
Triggered by Thread:  id of the thread where crashed = true

Thread[] crashed = true → Crashed
  Thread[].stack[0].i   Thread[].stack[0].fLine
  Thread[].stack[1].i   Thread[].stack[1].fLine
  Thread[].stack[2].i   Thread[].stack[2].fLine

Thread[] (not crashed)
  Thread[].stack[0].i   Thread[].stack[0].fLine
  Thread[].stack[1].i   Thread[].stack[1].fLine
```
